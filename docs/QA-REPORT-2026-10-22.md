## Reproduced functional defects

### F1 — High priority: phone user preview crashes over the Wi-Fi address

**Location:** `apps/web/components/workspace.tsx:86`; also UUID generation in `apps/web/lib/data.ts:5`.

**Reproduction:** open `http://192.168.0.104:3000` on the same network and select **Preview user view**. The admin screen opens, but switching to the customer screen renders “This page couldn’t load.” The browser records `TypeError: crypto.randomUUID is not a function`.

The customer component calls `crypto.randomUUID()` during mounting. That API is not available on this insecure LAN origin. The same workflow succeeds at localhost. Other preview mutations also call the same API, so the issue extends beyond the switch itself.

**Repair direction:** use an ID helper compatible with this supported local-preview transport, or supply an HTTPS preview; keep production identifiers and security requirements intact. Retest submission, approval and cancellation using the actual phone link.

Evidence: `qa-2026-10-22/phone-preview-crash.png` and browser console observation. This is a browser reproduction using the LAN address, not a physical-phone test.

### F2 — High priority: personal subject text survives account deletion in queued messages

**Location:** `supabase/migrations/202610180001_foundation.sql:224`.

**Reproduction:** a synthetic user submits a request with a distinct private subject; admin rejects it, sets retention to zero in the disposable database, then deletes the account with the correct confirmation. Two delivery jobs addressed to the administrator still contain the original subject.

Deletion removes jobs where the deleted user is the **recipient**, but does not remove or scrub jobs about that user's appointments addressed to another recipient. Pending messages can therefore still be delivered after the appointment and profile have been de-identified. This is not evidence of unauthorized public access; it is a failed deletion/de-identification safeguard.

**Repair direction:** apply deletion policy to all delivery payloads referencing the user's appointments, including other recipients and receipt references. Recheck data removal and pending delivery cancellation transactionally.

Failing test: `acceptance: deleting an account removes personal subject text from every delivery recipient`.

### F3 — Medium priority: NULL bypasses explicit deletion confirmation

**Location:** `supabase/migrations/202610180001_foundation.sql:217`.

**Reproduction:** an authenticated administrator calls `admin_delete_user(user_id, NULL)` for an otherwise eligible synthetic account. The account is deleted instead of rejecting the missing confirmation.

The SQL comparison with NULL does not evaluate to true, so the rejection branch is skipped. The caller still has to be an administrator; this does not grant a regular user deletion privileges.

**Repair direction:** explicitly reject NULL or use a NULL-safe comparison. Preserve active-appointment and retention checks.

Failing test: `acceptance: NULL deletion confirmation must not bypass typed confirmation`.

### F4 — Medium priority: an interrupted last delivery attempt can remain stuck forever

**Location:** `supabase/migrations/202610180002_delivery.sql:3–5`.

**Reproduction:** place a synthetic job in Processing with attempt_count 8 and a lease older than ten minutes, then call the claim function. It becomes Pending. The candidate query only selects attempt_count below 8, so the job cannot run again and is never marked Failed.

Ordinary provider failure on attempt 8 correctly becomes Failed; the defect concerns worker interruption/lease recovery.

**Repair direction:** terminalize exhausted expired leases and keep retryable leases eligible for recovery.

Failing test: `acceptance: abandoned final-attempt jobs must be Failed, not permanently Pending`.

### F5 — Medium priority: missing availability rules can erase the working calendar

**Location:** `supabase/migrations/202610180001_foundation.sql:202–203`.

**Reproduction:** as administrator, call `save_availability(NULL, [], [])`. The function succeeds instead of rejecting absent rules. The seven-day length comparison is NULL, then the existing rules are deleted and no replacements are inserted. The test transaction is rolled back to preserve the fixture.

Normal malformed duplicate weekdays do correctly roll back atomically. This defect is specific to missing/NULL input and requires admin access.

**Repair direction:** validate presence and JSON array types before replacing data, and require exactly seven distinct valid weekdays.

Failing test: `acceptance: NULL availability payload must be rejected without wiping working days`.

### F6 — Medium priority: backend accepts a malformed online meeting URL

**Location:** `supabase/migrations/202610180001_foundation.sql:130`.

**Reproduction:** approve a synthetic appointment through the authenticated admin RPC with location `https://meet.example.com not-a-valid-url`. Approval succeeds. The regular web helper rejects this input, but the server's expression only matches its prefix; native clients call this RPC directly.

**Repair direction:** validate the entire HTTP(S) URL on the server, reject whitespace and invalid host syntax, and align native/web/server behavior.

Failing test: `acceptance: online URL validation rejects embedded whitespace on the server`.

## Automated coverage details

The embedded database tests apply all three migration files and exercise real PostgreSQL constraints, row-level security and functions with mocked Auth identities. Coverage includes anonymous denial, role isolation, registration metadata escalation, field limits, email verification, suspension, notification ownership, profile/device access, unique active requests, idempotent retries, closed-key retries, hourly request throttling, working hours, breaks, blocked dates, duration limits, overlap exclusion, cancellation, completion/no-show cutoffs, reminder invalidation, retained history, account retention/deletion, sequence growth, receipt privacy, and calendar-edit preservation.

PGlite serializes queries. Tests named for a race exercise exclusion/order outcomes but **do not prove concurrency across independent deployed connections**.

Nine worker tests execute the actual TypeScript worker with database and HTTP boundaries mocked. They verify wrong method/secret rejection, absent cron secret, sanitized claim error, email idempotency header, transient retries, final provider failure, stale reminder cancellation, transactional in-app dispatch and no-token push behavior. Mock acceptance does not establish real provider delivery or native display.

## HTTP and performance observations

Local checks returned `/` 200, `/delete-account` 200, and an unknown route 404. Single measured local responses took 159ms, 74ms and 11ms respectively. These are smoke observations, not a load test or proof of the PRD's two-second mobile / three-second search targets.

## Remaining release tests

1. Configure a test Supabase project and real test identities. Verify registration, duplicate emails, verification, password reset expiry/reuse, email changes, token refresh/logout and suspended access through the actual network API.
2. Run independent-client races for request submission, overlapping approvals, cancellation versus approval, deletion versus submission, and reminder delivery versus rescheduling.
3. Configure test email/push providers and cron. Verify delivered content, retries, receipts, revoked tokens, background/terminated native states and short-notice reminders.
4. Install signed Android/iOS builds on physical devices. Verify layout, OS permissions, deep links, keyboard, secure storage, sharing, screen reader, large fonts, reconnect and real performance.
5. Test large datasets and pagination under concurrent changes, multi-page exports, additional browsers and time-zone/device-clock scenarios.
6. Verify backup restoration, monitoring/alerts, privacy/support pages, retention policy, production HTTPS and store requirements.
7. Repair the reproduced defects, rerun the preserved failing tests and repeat the relevant browser flows before release.
